### 自动获取

在页面点击深圳或山东的“填入已验证目录”，然后“获取并保存证据”。也可输入已知的同平台无条件开放库表目录编号。

- 深圳：`shenzhen/29200_00403632`。先获取开放属性、标题、元数据和字段，再调用公开预览，最多保留50行。有条件开放和仅文件目录直接提示，不尝试绕过申请。
- 山东：`shandong/20200618135541100100`。先读取目录开放属性、期间与字段，再请求首10行公开预览。不冒充全量API。
- 两者均调用 `POST /api/projects/{项目ID}/sources/local`，请求体 `{"query":"上述查询"}`。
- 模型可按地区请求这些已知目录；不得编造目录编号，也不得把预览样本或热度视为收入证明。

首次调用失败后只对连接故障和临时5xx最多重试3次；权限错误立即暂缓。来源URL、原始内容摘要哈希和每次失败写入source_runs/evidence。公开数据入库始终是外部、待核验、E0；核验后最多E1。

### 浏览器取数与再次导入

杭州：开放数据 → 搜索目录 → 无条件开放的数据集详情 → 数据预览。此次目录URL：
`https://data.hangzhou.gov.cn/dop/tpl/dataOpen/dataDetail.html?source_id=85742&source_type=DATA&source_type_str=A&version=1&source_code=jumMV/2026072017312623175`

广州：开放广东 → 搜索“广州市 养老” → 广州市养老机构开放信息 → 数据预览。此次目录URL：
`https://gddata.gd.gov.cn/opdata/index?chooseValue=collectForm&id=3070220100026%2F000025`

按当前公开表格重新采集，不读取浏览器登录凭据。保留原始行、字段、平台总量和实际采集范围；有重复记录只标记数量，原始记录不静默删除。生成UTF-8 JSON，字段为：

```json
{
  "region": "hangzhou",
  "title": "实际数据集标题",
  "source_locator": "实际官方详情页HTTPS网址",
  "data_period": "原数据所属期间；不知道则明确标记",
  "scope": "实际地区、样本行数、字段含义和局限",
  "retrieved_at": "2026-09-09T09:00:00+00:00",
  "content": "实际公开记录的JSON文本，不填写模拟内容"
}
```

页面“导入新的浏览器采集记录（JSON）”会放入本机共享快照库；再按项目选择“加入本项目证据”。导入会保留原采集时间，不更新为今天、不自动核验。也可执行：

```powershell
.\.venv\Scripts\python.exe scripts/import_local_capture.py data/hangzhou-local-capture.json
```

本机已导入杭州、广州两份真实快照，未向用户的东南亚防晒项目写入不相关证据。原始快照文件位于data目录，备份时随数据库一并备份；不包含网站密码或密钥。
