# 八维问答与报告审查

新建项目只需描述想法。第一轮问答结合用户原文识别项目类型、真实经营阶段和本次评估目的，记录引用；不确定时自然澄清。商业产品为客户提效不等于本企业内部提效，外部资料研究不套用内部立项审批。

前端明确显示两个阶段：

1. **第一阶段：正常问答。** 按八维检查项逐步整理。已有回答及明确未知的事项不重复索要；仍有可回答的关键问题时不收口。八维进度只衡量信息收集，后端确认本轮收集完成才达到100%。收集结束后自动在后台整理报告草稿，此时第一阶段显示“正在整理报告”。
2. **第二阶段：审查。** 草稿生成并保存后，前端显示“报告审查中”。一次审查对照原始问答、资料和评分标准检查事实限定、商业逻辑、风险与一致性。发现实质错误后修正报告及错误提取，由程序重新计算评级，再核对修订结果。通过后自动保存并展示最终报告，不再要求用户另点“生成报告”。

草稿、审查意见、修订记录保存在独立的后台 `report_workflows` 记录中，项目详情、任务轮询、项目列表只返回公开阶段和最终报告编号。审查完成前，草稿不写入项目proposal、阶段总结或正式报告列表。历史正式报告保持不变。

审查可以依据原文纠正模型提取的事实、分类和覆盖理由。程序拦截把“资料未取得”写成“不存在”的明确冲突，以及商业产品错误使用内部市场锚点。恢复unknown/external/future状态须依据该检查项已匹配的用户未知原话，不能改原始引文或提高核验等级。未知依据在报告保留，不能为了完成流程伪造数据或把系统失败当作NR。

发送审查请求时，相同的用户原文、项目描述、报告总结与理由、已应用的完整修订通过请求内引用去重。只替换完全相同且引用更短的内容，保留来源编号、对话角色与顺序；不同结论和未知状态分别保留。后台保存和校验仍使用完整上下文，模型输出必须填写实际原文与完整修订内容，不能把引用对象写入项目事实。格式重试和模型切换复用去重后的请求。

取消、断网、刷新或模型错误后保留处理步骤。重试复用当前草稿；已有修订时从修订核对继续，不重走问答或重写草稿。每次审查请求共享90秒总时限（含格式重试与模型切换），一次流程最多一次实质修订和一次核对。第二次仍有错误时不发布最终报告，允许继续核对或补充新资料。

草稿和完成状态绑定用户回答、有效项目事实、公司资料、证据、规则及覆盖状态。期间资料变化会使旧草稿失效，必须基于最新资料重新问答；完成报告使用稳定编号，重试不会重复保存。系统只以处理状态表示第二阶段进度，不随时间伪造百分比。

设计参考：[advisory-board SKILL.md](https://github.com/Backtthefuture/huangshu/blob/main/skills/advisory-board/SKILL.md) 的多视角质疑、逆向检验和有界收敛。SABC用一次模型请求覆盖四项职责，不模拟名人或以投票替代证据；通过审查不代表经营资料已独立核实。
