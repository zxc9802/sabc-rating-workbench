# 八维访谈与报告复核

借鉴 [黄叔私董会](https://github.com/Backtthefuture/huangshu/blob/main/skills/advisory-board/SKILL.md) 的决策相关追问、多视角审查和分歧验证方法。没有引入原版人物口吻、多人轮流发言、安装脚本或二次报告确认流程。

普通访谈在一次模型调用内考虑商业价值、执行资源、风险反方三个视角，选择最多两个影响决策且用户可回答的问题，仍使用原有八维标准。

用户点击生成报告，且初稿没有待追问的问题时，追加独立模型请求复核初稿。它使用现有模型路由及备用模型机制；“独立”指新的请求和审查角色，并不保证与初稿使用不同模型。复核获得有界事实、证据、最近报告及初稿，不共享初稿生成过程。复核期间不向聊天输出审查草稿。

复核必须覆盖三个视角，不能修改用户事实、发起新取数或引用未提供的证据。发现可答新缺口时清除评分建议并返回访谈；无法通过当前问答解决的缺口保留原因。完成修订后仍由确定性规则计算等级。失败或取消时不保存未复核报告。人工评审入口保留为人工流程，不伪装成独立模型复核。

报告快照保存初稿、修订判断、复核说明与问题，页面提供折叠的复核记录。后续交流清除项目当前的旧复核记录，历史快照仍保留；人工改写评分建议后不沿用旧复核标记。

验证包括普通访谈不触发复核、修订影响最终计算、新问题阻止报告保存、复核失败阻止保存、禁止修改事实/伪造引用，以及流式输出恢复。模型请求使用测试响应替代，真实模型质量、耗时和成本需要用固定项目案例另外比较；多视角一致不等同于证据得到验证。
