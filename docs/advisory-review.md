# 八维访谈与报告复核

借鉴 [黄叔私董会](https://github.com/Backtthefuture/huangshu/blob/main/skills/advisory-board/SKILL.md) 的决策相关追问、多视角审查和分歧验证方法。没有引入原版人物口吻、多人轮流发言、安装脚本或二次报告确认流程。

普通访谈在一次模型调用内考虑商业价值、执行资源、风险反方三个视角，选择最多两个影响决策且用户可回答的问题，仍使用原有八维标准。

访谈中八维已梳理、没有待追问的问题时，在同一轮生成内部判断并追加独立模型请求复核。内部判断不会自动保存为报告。它使用现有模型路由及备用模型机制；“独立”指新的请求和审查角色，并不保证与初稿使用不同模型。复核获得有界事实、证据、最近报告及初稿，不共享初稿生成过程。复核期间不向聊天输出审查草稿。

首次复核必须覆盖三个视角，不能修改用户事实、发起新取数或引用未提供的证据。发现可答新缺口时清除评分建议并返回访谈；无法通过当前问答解决的缺口保留原因。通过复核且项目事实已核对后，前端才展示“生成报告 / 继续补充”。用户点击生成时，直接使用已复核判断，由确定性规则计算等级并保存报告，不再次调用分析模型、复核模型或取数。失败或取消时不保存未复核报告。人工评审入口保留为人工流程，不伪装成独立模型复核。

复核提出问题后，保存内部初稿、当前问题、复核说明和输入指纹。用户补充回答时，若原项目资料、公司基线及证据未改变，直接调用复审模型，省去主模型重写初稿的请求。模型优先检查本次补充及关联维度，未受影响的判断沿用；预算、收益、资源或失败损失变化时扩大核对范围，必要时全面复核。仍有问题时只输出简短追问、覆盖状态与审查说明，不重写整份建议；全部处理完才返回完整修订判断。允许从本次回答提取待确认事实，不直接修改已确认资料。

原始资料或证据变化、当轮触发外部取数、或旧记录没有有效指纹时，走完整分析与独立复核。新增问答仍立即撤销旧生成授权。报告快照保存初稿、修订判断、复核说明与问题，页面提供折叠的复核记录；历史报告不受后续交流影响。人工改写评分建议后不沿用旧复核标记。

审查授权绑定项目事实、用户回答、公司版本、证据及其有效状态。新增访谈会立即撤销旧授权；其他输入变化会令授权失效。仅将待确认事实原样保存，不改变已审查内容时，无需重复审查。旧项目没有有效授权时需先继续核对。

验证包括有缺口的访谈不触发复核、收口时先复核再出现生成入口、点击生成不调用模型、输入变化使审查失效、修订影响最终计算、新问题阻止报告保存、复核失败阻止保存、禁止修改事实/伪造引用，以及流式输出恢复。模型请求使用测试响应替代，真实模型质量、耗时和成本需要用固定项目案例另外比较；多视角一致不等同于证据得到验证。

增量复审回归：连续两轮审查补充各调用一次复审、不重跑初稿；新问题继续阻止生成；修订分数进入最终报告；公司/项目/证据变更恢复完整审查；增量提取事实保持待确认。测试使用替代模型响应，不代表线上延迟测量。

使用 GLM-5.3 系列时，访谈、复审及报告答疑的调用顺序为：GLM 首次请求 → GLM 重试一次 → 同一服务地址及密钥的 `gpt-5.6-luna` → 已配置的 DeepSeek 备用服务。任一成功即停止回退，下次请求重新从主模型开始；取消任务不触发重试。GLM 的结构校验失败也计入这两次尝试，不叠加内部格式重试；其他模型保留现有格式校验机制。此回归验证调用顺序与凭据路由，未验证线上提供商对 Luna 的实际可用性。
