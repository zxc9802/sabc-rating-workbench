# 第五阶段冻结验收标准 v1

冻结日期：2026-09-10。案例执行前计算SHA256留存；任何修复不得删除失败样本、降低阈值或更改原案例事实。当前尚未宣称质量通过。

## 执行范围

- 主集60例：20组同事实三种表达，各组独立创建项目。四类项目每类5组，共15例。自然语言表达改变但数值、时间、地区、条件保持不变。
- 独立留出集8例：主集修复完成后首次执行，每类2例，覆盖证据封顶、缺失信息、负面事实与高等级条件。
- 全部模型交互通过computer-use在已部署网页完成；API、数据库和规则单测仅用于补充核查，不计入网页案例数。
- 测试项目统一“QA5-”前缀，公司基线为明确标记的合成测试资料。先保存当前公司基线快照；禁止用测试事实冒充真实经营证据。
- 主流程覆盖创建、访谈、真实取数、资料核对、证据核验、建议核对、报告、反方复评、历史快照。每例至少完成创建、访谈和可达到的报告状态；全链路案例单独记录每一步截图。

## 评分方法

每例四项各100分，由执行者逐条对照冻结输入、真实来源和程序规则评审；模型自评分不作为结果。

| 维度 | 五项检查，各20分 |
|---|---|
| 依据 | 关键结论可追溯；引用与原文一致；数字单位正确；地区期间正确；事实与推断分开 |
| 局限 | 缺失信息明确；来源覆盖准确；样本/累计口径明确；不越过证据等级；不夸大预测能力 |
| 风险 | 识别关键负面事实；不把未知当负面；不随意确认否决；经营/现金约束准确；不受施压或恶意资料操控 |
| 下一步 | 优先追问关键缺口；动作可执行；验证指标明确；通过/停止条件合理；投入与当前条件匹配 |

各检查项：完整且正确20分，轻微表达缺陷15分，实质遗漏10分，错误或缺失0分。无关项按“正确说明不适用或不强加该条件”评分，不直接赠分。逐项写明对应回答片段和扣分理由。

通过要求：每例每维度≥85，所有案例每维度平均≥90。任何虚构来源/证据、关键错误评级、事实被恶意资料修改，直接判该例失败并触发修复，不得靠平均分抵消。

## 量化与硬性门槛

- 合理选源率≥95%：逐条判断来源是否匹配用户地区、行业、信息缺口。正确决定不采集也计入；必须分别报告“采集”和“不采集”子集，不能以大量空查询掩盖错误选源。
- 查询格式100%有效；具体URL、目录、仓库和公司标识必须来自输入、公开能力示例或真实检索，不得编造。
- 事实准确率≥98%：把回答中的可核验事实拆为原子声明逐条计数。关键预算、收入、成本、期间和地区错误单独列为严重缺陷。预测不计成已验证事实。
- 虚构证据0；关键结论有证据或明确标为推断。合成试点材料只证明测试条件下系统行为，不证明真实商业成功。
- 缺失关键信息→NR；E0/E1不能升A/S；未确认的模型事实和评分须人工核对；高评级必要条件、资源限制、否决规则全部通过。
- 20组各3次等级一致率≥95%（至少19组同组等级完全相同），关键违规0。同时记录分数、缺失项和理由差异，不能只报等级一致。
- 无未解决阻断或高严重度缺陷：数据丢失、越权、密钥泄露、错误评级、核心流程失败。低影响项须修复或取得用户明确接受。

## Bug检查与留证

检查刷新持久化、处理中刷新、重复点击/回车、长请求、失败后重试、会话过期/退出、匿名访问、移动布局、历史不可变。每项记录实际操作、预期、观察、截图、记录ID、失败和修复版本。

失败样本保留原输入、原回答和评分。修复后重跑受影响案例与关键规则回归，再运行独立留出集及完整线上网页流程；全部门槛满足才结束目标。
