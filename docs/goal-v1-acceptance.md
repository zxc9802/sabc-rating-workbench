# Goal v1 验收清单（2026-09-12，测试前冻结）

依据：用户提供的《SABC项目评级智能体_V1.0正式标准.txt》。以下“§”为该文档章节；“约定”为本线程确认的产品行为。清单在 Mixtoken 部署后的首轮浏览器测试前冻结，后续不能删除失败项或改变分母。

## 范围与判定

- 三个独立案例：T 泰国防晒，I 内部提效，R 明显风险。每个案例逐轮访谈、用户点击生成、报告答疑及刷新保存。
- 默认所有条目适用于每个案例；T/I/R 列明确标记的类型例外在测试前固定。实际没有触发的关键路径必须补测，不能直接算通过。
- P=有线上操作证据通过；F=失败；U=未测或证据不足（计入分母，不计通过）；N=此处预先规定的不适用项。每个案例 P/(P+F+U)≥90%；标★的适用项必须全部通过。
- 数值公式、证据封顶及调用次数允许以同一部署版本的服务端记录/确定性回归补充，但单纯本地模拟不能代替线上访谈、报告与答疑。
- 约定例外：保留单流程、暂缓评级；缺证据不自动扣成 C；不恢复三阶段 UI；同次分析融入反方内容，不增加独立审查调用；报告由用户点击后才生成。
- 文档§15跨项目PK未覆盖，不进入本轮分母。§20建议性阶段与类型标签不作为必选 UI 改动。
- 测试输入属于验收案例：可陈述方案、预算约束和假设；无真实凭证时，不伪称真实订单、报价、利润或已核验结果。不得以特定等级为目标编造依据。

## 预设探针与答疑

T：从“我想做东南亚项目”逐步到泰国OEM防晒/TikTok；先只回答产品国家；报价、销量、备案与泰语能力有缺口；先给测款预算2万，随后明确更正为1.5万，总上限3万、最大损失1.5万，均为方案约束而非已验证账目；ROI说明口径并区分利润。

I：店铺内部订单对账辅助，人工复核，无自动退款/资金权限；先不给完整投入信息；以工时与差错减少为目标，明确不裁员、工时不是现金节省；数据处理授权/模型保留政策未知，未获确认前仅脱敏样本。

R：评估一个存在明确不利单位模型及高库存/现金风险的原方案；数值是用户提出方案的测算输入而非伪造真实凭证；承认成本结构、无改善路径，不用“老板希望A”覆盖风险。若证据不足以触发已核验红线，允许暂缓，必须明确拒绝批准原高风险投入。

每案答疑：为什么该等级；ROI/净利润（I为工时/现金）如何算；事实与假设；预算改变影响；能否直接给缺失数据确定答案。补一次承接追问并检查报告未被修改。

## 记录约定

线上原始记录、截图、耗时与结果表保存在本地 artifacts/goal-v1/（不推送含业务细节的资料）；本文件和必要修复进入Git。每次失败保留首轮证据，另记录修复提交、部署提交及复测证据，不覆盖失败历史。

## 2026-09-12 用户追加：先核实已有测试，再判断证据缺口

原 V1 的56项、历史分母与失败记录保持不变。用户要求后续测试允许增加问答轮数，以关键事实问清楚为收口依据。运行时八维检查从27项增加到31项，新增测试经历、实际结果、记录来源、类似案例四项；不新增独立审查调用，不改变评级门槛或自动升级证据。

测试方法：

1. 不在助手询问前主动把“尚未测试/有实测结果”及全部关键槽位一次填全，避免测试者替产品完成追问。用户自发已说明的路径另测“不重复问”。
2. 在独立访谈分支复测：未说明经历；只说做过；仅有未来目标；有结果但没有记录；明确未测且没有类似案例；有类似案例但条件不同；后续新增或纠正测试结果。不伪造真实交易、试验或成功证据，合成正向资料在隔离测试中明确标注。
3. 逐轮对照“助手问了什么、用户回答了什么、哪些仍需问、哪些明确未知”。不限制总轮数，每轮1至2个聚焦主题；同一项已明确回答后不换措辞再问。
4. 收口前核对全部31项。未点击生成不得产生报告草稿；点击后报告区分未测、已测但材料不足、已核验结果，不能用缺少记录推断没有测试。保留每轮耗时、进度、原始对话和失败截图。
